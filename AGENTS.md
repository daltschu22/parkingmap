# AGENTS.md

## Project

`parkingmap` is a FastAPI web app for visualizing street and parking-rule data on an interactive map.

The goal is an accurate interactive parking map for Boston and surrounding municipalities such as Cambridge, Somerville, Medford, and nearby towns.

The app should answer the practical question: can someone park at a specific curb location, and under what rule? Whole-street labels are not accurate enough. If a street has one meter, one loading zone, one resident-only side, or one partial restriction, do not mark the whole street with that status.

Each city may be its own ingestion challenge. Expect city-specific data sources, PDF formats, maps, ordinances, GIS exports, and parser quirks. Build shared output models and confidence fields, but keep city-specific extraction logic where needed.

Official public data comes first. Download and preserve PDFs, maps, HTML pages, GIS files, and other source artifacts when they are needed to reproduce parsing. Some sources will require PDF text extraction; some may require OCR or manual georeferencing. Street-level imagery, sign recognition, meter detection, or DGX-backed image processing can be considered later when official sources are missing or need verification, but imagery should not replace official rules without confidence/source notes.

Current implemented coverage starts with Somerville, Medford, and Cambridge. Medford permit rows and Cambridge meter polygons are intentionally retained as segment evidence until curb matching exists.

## Commands

- Install dependencies: `uv sync`
- Rebuild derived parking rules: `uv run python build_parking_rules.py`
- Fetch Medford public sources: `uv run python scripts/fetch_public_sources.py --municipality medford`
- Build Medford street geometry: `uv run python build_medford_streets.py`
- Build Medford resident-permit seed rules: `uv run python build_medford_rules_seed.py`
- Build Cambridge street geometry and parking summaries: `uv run python build_cambridge_data.py`
- Build Somerville/Cambridge public lot and garage points: `uv run python build_public_parking_facilities.py`
- Build coverage and Medford segment evidence: `uv run python build_parking_coverage.py`
- Build Mapillary imagery metadata: `MAPILLARY_ACCESS_TOKEN=... uv run python scripts/build_imagery_index.py --provider mapillary --municipality somerville --limit 25`
- Run the app: `uv run python -m parkingmap`
- Run without `uv`: `python -m parkingmap`

The app serves on `0.0.0.0` and reads `PORT` from the environment.

## Notes

- `data/parking_rules_by_street.json` is generated by `build_parking_rules.py`.
- Medford source files are tracked in `data/source_manifest.json`; downloaded files live under `data/raw/medford/`.
- Medford street geometry is built from MassGIS/MassDOT Roads into `data/processed/medford/streets.geojson`.
- Medford segment-level evidence is generated into `data/processed/medford/segment_parking_evidence.json`.
- The combined coverage summary is generated into `data/processed/parking_coverage_report.json`.
- Cambridge street geometry, meter/accessibility evidence geometry, and first-pass summaries are built from Cambridge GIS into `data/processed/cambridge/`.
- Street-level imagery metadata is generated into `data/processed/imagery/street_imagery_index.geojson`; do not commit local API tokens or raw image bulk downloads without checking source licensing.
- DGX Spark image batch planning lives in `docs/SPARK_IMAGE_WORKLOAD.md`; image detections remain evidence until reviewed or matched to stronger rule sources.
- Cambridge metered-space polygons are nearest-matched to street centerlines; they are not exact curb extents and must not make an entire street "metered."
- Parking-rule matching is currently street-name based, not block-segment precise.
- Do not collapse partial, side-specific, address-range, or from/to-block rules into whole-street statuses.
- Preserve source attribution, source file paths, raw extracted text, and parser confidence wherever practical.
- Prefer curb segments as the long-term unit of truth: side of street, start anchor, end anchor, rule, active time, source, and confidence.
- Keep changes focused on the app, parser, and local data files already in this repo.
- Avoid broad rewrites unless they are needed for the requested behavior.
